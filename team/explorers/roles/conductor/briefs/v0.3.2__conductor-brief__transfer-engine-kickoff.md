## Context

The human stakeholder (Dinis Cruz) has issued a comprehensive research brief defining the architecture, principles, and research agenda for the file transfer engine — the core component of SGraph Send. This Conductor brief decomposes that brief into role-specific tasks and establishes priorities.

## Key Architectural Decisions (from brief)

1. **Encryption is a callback** — the transfer engine is transport-agnostic; encryption plugs in as an adapter
2. **Pure JavaScript, multi-runtime** — runs in browser, Node.js, Deno, Bun from day one
3. **Compress before encrypt** — this pipeline order is invariant
4. **Transfer manifest is single source of truth** — JSON document governing every transfer
5. **Three-level progress visibility** — simple, stage detail, raw technical
6. **Phase 1 (core engine + CLI) before Phase 2 (browser integration)**

## Current Priority Order

2. **Architect + DevOps**: In parallel, work on R1 + R4 (S3/platform research)
3. **Architect + Dev**: In parallel, evaluate R2 (tus/Uppy/Resumable.js)
4. **Dev**: R3 (browser storage research) can proceed independently
5. **DevOps**: Set up initial CI pipeline while research proceeds
6. **AppSec**: Review the manifest schema design and crypto adapter interface once available
